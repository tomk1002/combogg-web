# /review

`/pr` 호출 전 셀프 리뷰. 시니어 엔지니어 관점에서 가차없이 점검.

## 검토 항목

### 1. 명세 일치
- API 변경이 `docs/04_shared_spec.md`와 일치하는가?
- DB 스키마 변경이 명세에 반영되어 있는가?
- 게임별 변경이 `docs/04_shared_spec.md` 4.5절(게임 추가 체크리스트)을 따르는가?

### 2. 코드 품질
- 명백한 버그·엣지 케이스 미처리
- 에러 처리 누락
- 타입 안전성 (any 남용, 단언 남용)
- 보안 (인증 우회 가능성, 입력 검증)

### 3. 테스트
- 새 기능에 테스트가 있는가?
- 기존 테스트가 깨지지 않는가?

### 4. 의존성
- 새로 추가된 의존성이 정당한가?
- 라이센스 호환성 (특히 GPL 계열)

### 5. 문서
- CLAUDE.md 업데이트 필요한가?
- 환경변수 추가 시 `.env.example` 반영했는가?

## 출력 형식

```
## 셀프 리뷰 결과

### 🚨 차단 (PR 전 반드시 수정)

### ⚠️ 권장

### 💡 제안

### ✅ 잘된 점
```

차단 항목 있으면 PR 만들지 말고 먼저 수정 권유.
